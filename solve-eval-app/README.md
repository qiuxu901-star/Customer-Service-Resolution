# 客服 AI 解决能力价值评估 · 应用

由《业务需求及评估标准 V2.1》《PRD V1.0》《检测规则清单 V1.0》三份文档直接构建的最小可用应用：**和评估助手对话获取数据与分析结论 → 输入会话检测 → 信息不足时提问 → 结果落入人工复核平台 → 全盘记录 + 数据看板 → 材料就绪度追踪 → 同口径复验**。

## 启动

```bash
cd solve-eval-app
/Users/qiuxu/.workbuddy/binaries/node/versions/22.22.2-6/bin/node server.js
# 本机打开 http://localhost:8817
```

零外部依赖（Node 原生 http + JSON 文件存储），数据在 `data/db.json`。默认进入「评估助手」视图。

## 局域网共同访问（多人协作）

服务默认绑定 `0.0.0.0`，启动时自动打印所有局域网地址，例如：

```
解决力评估应用已启动（局域网共享模式）:
  本机:   http://localhost:8817
  局域网: http://192.168.0.41:8817   [en0]
```

同一局域网内的同事直接访问 **http://192.168.0.41:8817**（以启动日志打印的实际地址为准）即可共同使用，无需各自部署。多人共用已做适配：

- **操作人按浏览器独立**：每人在「设置」页填自己的名字（存本浏览器 localStorage），复核记录各自署名，互不覆盖；全局设置里的操作人仅作兜底
- **并发保护**：同一复核记录的终态操作（确认/修正/标U/裁决）先到先得，后到者收到 409 提示"该记录已被 XX 处理"，不会静默互相覆盖；历史留痕保留双方动作
- **自动刷新**：徽标与当前视图每 20 秒自动同步（切到别的窗口、正在输入、弹窗打开时不刷，避免打断）
- 数据为单进程内存 + 同步落盘，多人同时读写无竞争问题

注意事项：
- 若他人打不开：macOS 检查「系统设置 → 网络 → 防火墙」是否拦截了 node（允许"传入连接"）；或确认双方在同一局域网（同一 Wi-Fi/交换机）
- 关闭本机或退出服务后他人即无法访问，数据仍完整保留在 `data/db.json`
- 仅建议在可信内网使用，应用未内置登录鉴权

## 功能地图（对应 PRD 模块）

| 视图 | 对应模块 | 能力 |
|---|---|---|
| 评估助手 | Agent | 对话式取数（指标/分布/队列/检索/归因）、对话中直接提交检测、材料就绪度问答、分析结论生成；规则路由 + LLM 工具调用双通道，trace 可追溯 |
| 检测台 · 单条 | F1 / F2 / F3 | 粘贴会话 + 元数据 → 引擎按规则清单十二段检测 → 三段式报告（结论-依据-不确定性）+ 追问 |
| 检测台 · 批量 | F1.2 / F1.4 | JSON 数组或 CSV 导入（含模板下载），逐条实时检测，结果全部落入复核台 |
| 人工复核台 | F4 | 六态看板 + 优先级筛选（U/L0 优先、L3 抽检），确认/修正/补证/标U/提交标准事项/争议/裁决/派生纠正任务，原结论保留 |
| 数据看板 | F5 | 核心四指标（可点击下钻）+ 五层指标 + 按意图/按场景下钻表 + U 专区，全部注明分子分母 |
| 全盘记录 | F8 | 会话/诉求/结论/复核全量留痕，搜索 + 四维筛选（等级/意图/场景/复核态），JSON/CSV 导出 |
| 材料中心 | F6 延伸 | 9 类材料就绪度看板（为什么需要/提供格式/进度）、6 个模板下载、CSV/JSON 批量导入标准 |
| 标准库 | F6 | 六类标准维护、状态机（草稿→待确认→已生效/已冲突）、版本管理、标准事项跟踪 |
| 纠正任务 | F7 | 从复核台派生，四态流转（待纠正→纠正中→待复验→已关闭），区分「原 AI 能力修正」与「评价标准修正」 |
| 设置 | F10 | 操作人、抽检比例、大模型配置（OpenAI 兼容，同时驱动引擎与助手） |

## 同口径复验（V2.1 6.3 闭环）

标准更新后，在全盘记录打开任意会话 → 「执行同口径复验」：用当前标准重跑同一样本，前后等级对比展示；复验样本不计入默认统计口径，防止样本变化造成“虚假提升”。

## 检测引擎双模式

- **规则模式（默认）**：未配置大模型时运行。按规则清单执行诉求还原、意图/场景检测、七维度启发式检测、G1-G4 判级。保守判级：无标准定义时按 I3/S3 输出 U；不得因未发现错误给 L3（G9）。
- **LLM 模式**：设置页填入 OpenAI 兼容接口（Base URL / Key / Model）后切换。prompt 完整编码 P1-P5、G1-G4、D1-D7、U01-U09 纪律；调用失败自动降级规则模式并标注。

## 评估助手问法示例

```
当前完整方案可交付率是多少？      无法判断的原因分布？
待复核还有多少？优先处理哪些？    按意图看一下 L3 率 / 场景匹配怎么样
人工剩余工作                    主要问题集中在哪
搜索会话：奖励                  给我分析结论
我还需要提供哪些材料？           导出检测结果
检测这段对话：司机：… 意图：… 场景：… AI建议：…   （或直接粘贴多轮会话）
```

外部 Agent 通过 `POST /api/agent/chat` 走同一入口，契约见工作区《Agent对接与数据获取说明.md》。

## 关键纪律（已编码进引擎与界面）

1. 缺失即标记、不补造（R2/R4）；阻断级缺失先追问（need_input）。
2. 无意图/场景定义 → U（I3/S3），不凭名称相似下结论。
3. 风险控制维度一票否决并倾向 L0（D7/B5）。
4. 关键维度缺证据 → U，带原因代码与待补齐方（G2/UR1）。
5. 司机致谢只记录不评价（B7/F3.5）。
6. 原检测结论永不被覆盖，人工结论独立留痕（PRD 规则 5/7）。
7. L3 按比例随机抽检（默认 10%），防止只发现误报（V2.1 6.3）。
8. 看板指标分母口径统一，无法判断与能力指标并列披露（V2.1 7.5）。
9. 复验样本与正式样本分流统计，改进前后同样本同口径对比（V2.1 6.3/7.5）。
