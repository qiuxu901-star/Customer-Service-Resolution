# 客服表现评估

承接已完成场景、对象、监测方案和执行流程确认的一条评估任务。公共评估规则提供等级和证据要求；所选场景方案提供业务检查条件，具体工单提供事实材料。

宿主执行器按发布的流程准备材料、执行可选程序检查、调用模型、校验并保存报告。模型负责“场景表现评估”步骤，不执行规则文档提到的外部业务操作。

执行方法：

1. 明确当前任务及适用范围，识别默认展示的责任结论、点击详情可见的其他AI信息、原始上下文、人工背景和独立证据。二线整体表现结合结论与可见详情；可读性区分两层，不要求详情在结论中重复。
2. 明确客服需要什么帮助，结合所选场景方案检查 AI 已完成什么、材料如何支持、减少了客服哪项工作。
3. 区分人工只需补充确认还是需要重做核心工作，检查已确认关键错误，检查输出是否便于客服理解结论、依据、待核实及下一步，再按公共标准汇总帮助程度。列表摘要展示关键点是什么、没解决什么、可读性怎么样；详情先展示评估结论（关键点是什么、没解决什么），再展示AI输出可读性、具体问题与依据；任务范围随结论说明，具体帮助、剩余工作和待核实事项供展开复核；已确认的理解障碍提供依据及按现有材料改写的示范，详细检查用于复核。
4. 按宿主输出协议返回结构化报告与引用编号。格式、引用和评分校验由宿主执行。

仅使用本条加载的场景资源，不自行选择其他场景方案。程序检查的缺失或未匹配结果是核验线索，不直接证明业务错误。人工评价标签不参与初评。

本阶段不读取客服业务 Skill，不确认 Skill 定义缺陷或执行根因。用户明确选择问题和业务 Skill 版本后，由独立诊断能力继续处理。

在本平台中，执行入口为 `evaluation-capability.js` 的 `runFlow`；可用步骤、条件、输入输出和版本由平台登记。公共规则、场景分支和流程草稿在“评估员 Skill”页面维护并版本发布。
